# Handoff: normal / shading parity (`claude/normal-shading-parity`)

Base: `gpt/integrated-three-fronts`. Untouched: UV, brush, painting, Project Settings, PR #3/#4.

## Proven cause
Compared against Blender 4.0.2 (Cycles) reference data (`src/test_data/*.json`, generated by `scripts/blender_normal_reference.py` and `scripts/blender_tangent_reference.py`):
- MikkTSpace tangents match Blender per corner (0/136 triangles differ, incl. tips, polar fans, mirrored UVs). `tangentW = -1` is correct for mirrored UVs, not an error.
- Normal-map decode and tangent->world match Blender for every front-facing case, normal/inverted UVs, consistent/opposed imported normals.
- **Bug found:** on back-facing fragments the tilt along U (tangent X) was mirrored vs Blender (raster and path tracer). Blender negates the whole mapped normal when seen from behind; the viewport flipped only the shading normal and kept tangent + handedness.

## Change (minimal, back faces only)
- `view.wgsl`: `if (!front) { tangent = -tangent; handedness = -handedness; }` before building the bitangent.
- `pathtrace.wgsl`: same rule in `mesh_surface` (`back_face`).
- New diagnostic view modes (3D display dropdown > SHADING DIAGNOSTICS): geometric normal, shading normal, tangent, bitangent, mapped normal, grazing clamp.

## Tests
- `normal_parity_test::mikk_tangents_*` (CPU, pass).
- `normal_parity_test::raster_normal_map_frame_matches_blender` (GPU, real shader, 288 readings): 0 mismatches with fix, 32/288 without.
- Existing `preview_test::raster_normal_map_*`, `raster_view_is_stable_with_inverted_shading_normals` pass.
- Non-ignored suite: 139 passed.
- `preview_test::cage_paint_and_auto_fix` fails identically on the base branch (pre-existing, unrelated).

## Unresolved / limitations
- Path-tracer patch is NOT executed under test: the path-tracer compute shader segfaults Lavapipe (even on a stock cube). `raster_and_path_tracer_lighting_follow_blender_normals` is `#[ignore]` and needs a real GPU.
- Fix affects only back-facing fragments (cables, thin parts, open edges); it does not explain a global look difference vs Blender/InstaMAT. Remaining candidates (lighting/env/tonemap/BRDF differences, FBX import with negative determinant, real Airfox asset) are unverified.
- The 12 opposed Airfox triangles are face-forwarded on purpose (viewport differs from Blender's inside-out shading).
- Owner must validate on his machine.
